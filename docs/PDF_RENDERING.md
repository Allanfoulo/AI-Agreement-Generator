# PDF rendering

Brief Doc X renders issued documents through the PDFCN/Takumi approach:

- The source-owned template lives in `src/pdf/templates/structured-document.tsx`.
- `takumi-pdf` provides JSX-to-PDF rendering, A4 pagination, selectable text, and page primitives.
- The Convex Node action in `convex/pdfRender.ts` owns the runtime-only renderer boundary.
- `convex/render.ts` remains the event-driven job state machine: claim, retry, checksum, storage, and completion event.
- `pdf-lib` is retained only to verify the generated bytes and page count; it is no longer the renderer.

Template selection is part of the document contract. Quote and invoice drafts support the `modern`, `corporate`, and `minimal` families; the selected `templateKey` is normalized and persisted by Convex, copied into the immutable issued-version snapshot, and used by the PDF template. Accepted-quote conversion accepts an explicit invoice template key so the final invoice can use a different family from its source quote. Existing non-financial document keys remain compatible with their `general` and `standard` templates.

The Takumi WebAssembly asset is pinned through `TAKUMI_WASM_URL`. The default points to the installed `takumi-pdf` version. Set the Convex environment variable to an internal asset URL in deployments that do not allow outbound fetches.

PDFCN is distributed as copyable registry source rather than a runtime package. The implementation follows the official PDFCN registry model while keeping Brief Doc X-specific document structure and styling in the repository.
